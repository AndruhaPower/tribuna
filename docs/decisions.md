# Журнал решений Tribuna

Зафиксированные решения и известные грабли. Перед работой прочитай целиком. Принял новое решение или наступил на грабли — допиши сюда в том же коммите.

Формат записи: номер, дата, решение, почему, следствия. Отменённое решение не удаляем, а помечаем «Отменено → D<N>».

## Решения

### D1. Репозиторий — 2026-11-19
Приватный GitHub `AndruhaPower/tribuna`, основная ветка `main`. Автор коммитов — `pazit@yandex.ru`, задан локально в `.git/config`, глобальный git не трогаем.
Код, правила и инфраструктуру других проектов сюда не переносим.

### D2. Цель — App Store — 2026-11-19
Проект строится как продукт для публикации и развития, не как прототип. Архитектуру закладываем сразу, без «перепишем потом».

### D3. Минимальная iOS 16 — 2026-11-19
Следствия: нельзя Observation (`@Observable`), SwiftData и прочие API iOS 17+ без `if #available`. Для реактивности доступен Combine.

### D4. Tuist, проект генерируется — 2026-11-19
`.xcodeproj` и `.xcworkspace` не хранятся в git, генерируются Tuist. Генерация одной командой из корня: `./generate`. Версия Tuist закреплена в `mise.toml`.

### D5. Модуль на каждую фичу — 2026-11-19 (`FeatureBookmarks` удалён → D38)
- `Tribuna/` — приложение, собирает фичи (таб-бар, DI, точка входа).
- `Features/Feature<Имя>/` — по модулю на фичу (экраны `Матч` и `Плеер` не вкладки, но тоже фичи): `FeatureToday`, `FeatureMatch`, `FeatureBookmarks`, `FeatureRadio`, `FeaturePodcasts`, `FeaturePlayer`, `FeatureProfile`.
- `Core/Core<Имя>/` — общий код (сеть, хранилище, аудио, дизайн-система). Модуль заводим, когда он нужен первой фиче, а не заранее.
- Фичи не зависят друг от друга. Общее выносим в Core. Core не зависит от фич.

### D6. UIKit + SnapKit, Swift 6 — 2026-11-19
UI на UIKit, вёрстка кодом через SnapKit (без storyboard и xib, кроме системного Launch Screen из Info.plist). Жизненный цикл — `AppDelegate` + `SceneDelegate`.
Swift 6 language mode со строгой проверкой конкурентности с первого коммита: потом мигрировать дороже.
Внешние зависимости подключаются через `Tuist/Package.swift`, `Tuist/Package.resolved` коммитится.

### D7. Бэкенд в этом же репозитории — 2026-11-19
Supabase-проект `tribuna_db`. Миграции и Edge Functions лежат в `supabase/` этого репозитория.

### D8. Футбол только через бэкенд — 2026-11-19
У football-data.org лимит ~10 запросов в минуту на ключ, общий для всех пользователей. Поэтому клиент не ходит в football-data.org: Edge Function или cron забирает матчи в таблицу Supabase, клиент читает оттуда. Пуш «за 15 минут до матча» тоже шлёт сервер. NHL, Radio Browser и iTunes ключа не требуют, их клиент вызывает напрямую.

### D9. Секреты не в git — 2026-11-19
Ключи API, `.env`, `Secrets.xcconfig`, `.p8`, `.p12` — только локально и в настройках Supabase. В репозитории допустим `.env.example` без значений.

### D10. Bundle ID — 2026-11-19
Приложение: `com.tribuna.app`. Модули: `com.tribuna.app.<Модуль>`. После публикации в App Store не меняется.

### D11. Граница модуля фичи — 2026-11-19
Фича наружу отдаёт только фабрику: `public enum Feature<Имя> { public static func make...() -> UIViewController }`. Всё остальное `internal`. Приложение собирает фичи и решает, что куда ведёт.
Пока все модули — таргеты (static framework) в одном `Project.swift` в корне. На отдельные проекты делим, если сборка станет медленной.
Паттерн экрана (MVVM, координаторы и т.п.) выбираем на первом настоящем экране и записываем сюда.

### D12. Макеты — 2026-11-19
Источник дизайна — только PNG в `docs/design/` (Figma нет). Размер 780 px = 390 pt @2x: отступ 40 px в макете = 20 pt.
Цвета сняты по пикселям и лежат в `CoreUI/Palette.swift` — новые цвета добавлять туда же, хардкод цветов в фичах запрещён.

### D13. Только тёмная тема — 2026-11-19
В макетах только тёмная тема. `UIUserInterfaceStyle = Dark` в Info.plist, светлую тему не поддерживаем.

### D14. Четыре вкладки — 2026-11-19
Сегодня, Эфир, Подкасты, Профиль. Отдельной вкладки «Закладки» нет: закладки видны в «Мои события» на «Сегодня» и в «Мои закладки» в профиле. `FeatureBookmarks` остаётся модулем экрана списка закладок, открывается из профиля через приложение (фичи друг друга не знают, D5).

### D15. Плеер общий для всего приложения — 2026-11-19
Воспроизведение запускают Сегодня («Слушать эфир матча»), Матч («Слушать под матч»), Эфир и Подкасты, а мини-плеер висит над таб-баром на всех вкладках. Поэтому:
- движок воспроизведения (AVPlayer, экран блокировки, фоновое аудио, позиция) — в Core-модуле, заводим как `CorePlayback`;
- мини-плеер и полноэкранный плеер — в `FeaturePlayer`;
- прикрепляет мини-плеер к таб-бару приложение.
Плеер подкаста: скорость, −15/+30 с, таймер сна, загрузка, «Поделиться». Для радио тот же экран без перемотки и скорости (макета нет, предложение).

### D16. Контент редакции на бэкенде — 2026-11-19
Ни одно API не отдаёт: связку матча со станцией и подкастом («Слушать под матч»), «Подборку редакции» в Эфире, «Подборку» в Подкастах, русские названия команд и их аббревиатуры (LIV, ARS). Всё это — таблицы Supabase. Гербы клубов — см. D26 (в макетах кружки с аббревиатурами).

### D17. Время по местному дню — 2026-11-19
Матчи группируются по дню в часовом поясе пользователя, не по UTC. Ночные матчи НХЛ подписываются «ночь на чт».

### D18. Шрифты — 2026-11-19
- Unbounded 500 и 700 — заголовки экранов, логотип TRIBUNA, крупный счёт матча, цифры в профиле.
- SF Pro (системный) 400–700 — весь остальной текст: списки, подписи, кнопки, таб-бар.
Unbounded — вариативный файл из Google Fonts (`Tribuna/Resources/Fonts/Unbounded.ttf`, лицензия OFL рядом), регистрируется через `UIAppFonts`. Вес задаётся осью `wght` в `Typography.display(_:_:)`; по имени PostScript (`Unbounded-Regular_Bold`) не обращаемся. Шрифты в фичах — только через `Typography`.
Размеры сняты с макета «Сегодня» по высоте заглавных: `Typography.screenTitle` — Unbounded 700 30 pt, логотип — Unbounded 16, счёт в карточке — Unbounded 24; аббревиатура команды (`TeamBadgeView`) — SF 12 semibold, заголовок секции (`SectionHeaderView`) — SF 14 semibold капсом, подпись справа — SF 13. Макет отрисован чуть более узким шрифтом, чем SF в UIKit, поэтому ширина надписей расходится до ~3 pt — подбирай размер по высоте букв, не по ширине.

### D19. Свой таб-бар — 2026-11-19
Системный таб-бар в iOS 26 плавающий «стеклянный», в макете плоский. Используем свой: `MainTabBarController` (контейнер вкладок) + `TabBarView` в приложении. Размеры замерены по пикселям макета: высота 49 pt без безопасной зоны, поля 12 pt, иконка в квадрате 22 pt с верхом на 9.5 pt, базовая линия подписи 47.7 pt, подписи SF 11 pt (semibold — активная, medium — остальные).
Иконки — геометрия Lucide (ISC, `Tribuna/Resources/Lucide-LICENSE.txt`), SVG в `Assets.xcassets/tab-*`, линия 2. В макете иконки разного масштаба, поэтому масштаб каждой подогнан её `viewBox`, а не размером в коде. SF Symbols для таб-бара не используем — не совпадают с макетом.
Вкладкам добавляется `additionalSafeAreaInsets.bottom = 49`. Мини-плеер (D15) кладётся в тот же контейнер над таб-баром. `UIDesignRequiresCompatibility` не используем — Apple его уберёт.

### D20. Футбол: pg_cron → Edge Function → таблицы — 2026-11-19
Данные football-data.org попадают в Supabase так: pg_cron вызывает Edge Function `sync-football`, она забирает матчи, команды и таблицы и пишет в таблицы `competitions`, `teams`, `matches`, `standings`, `sync_state`. Клиент только читает их (RLS: `select` для `anon`/`authenticated`, писать может только `service_role`; `sync_state` клиенту закрыта). Таблицу турнира заменяет атомарно `replace_standings` (`security definer`, `execute` только у `service_role`). Схема — `supabase/migrations/20261119120000_football.sql`, дизайн — [спек](superpowers/specs/2026-11-19-football-backend-design.md).
Live-окно: TIMED/SCHEDULED считаются live в диапазоне −3 ч…+15 мин от `utc_date` (статус у football-data меняется с задержкой), `EXTRA_TIME`/`PENALTY_SHOOTOUT` — live. Таймаут `net.http_post` в cron — 30 с.

### D21. Паттерн экрана и слой данных — 2026-11-19
Экран — MVVM: `@MainActor` ViewModel с `@Published private(set) var state`, State уже отформатирован для показа, ViewController только рисует. Публичная поверхность фичи — `Feature<Имя>.make(dependencies:output:)`, наружу фича общается замыканиями `Output`. Координатор заводим, только когда в фиче больше одного экрана. Коллекции: compositional layout + diffable data source со стабильными ID и `reconfigureItems` для обновления ячеек. Экраны с зависящими от времени данными реагируют на `willEnterForeground` (перезагрузка, смена суток) через метод ViewModel `didEnterForeground()`.
Модули: `CoreDomain` — модели и протоколы, без зависимостей; `CoreRepositories` — реализации (PostgREST, UserDefaults), от него зависит только приложение, фичи видят лишь протоколы из `CoreDomain`.
Закладки пока локальные, в UserDefaults (ключ `bookmarks.v1`, элементы `<спорт>:<id матча>`); синхронизация с бэкендом — позже. Publishable-ключ Supabase лежит в коде приложения (`AppConfig`): он публичный по замыслу, доступ ограничен RLS (только чтение), поэтому это не секрет из D9.
Тесты — Swift Testing, схема = имя модуля:
```
xcodebuild test -workspace Tribuna.xcworkspace -scheme CoreRepositories -destination 'platform=iOS Simulator,name=iPhone 17 Pro Max,OS=26.0.1'
```
Спек — [foundation-today](superpowers/specs/2026-11-19-foundation-today-design.md).

### D22. Карточка матча — 2026-11-19
- Подпись «Счёт обновляется с небольшой задержкой» показывается только для футбольного матча в статусе `live`/`paused`.
- Шапка карточки — своя, не системная панель: круглые кнопки 44 pt «назад» и «поделиться» (Lucide `chevron-left`, `share`) как в макете, панель навигации скрыта, шапка закреплена над прокруткой. Свайп «назад» при скрытой панели не работает сам — карточка на время показа становится делегатом `interactivePopGestureRecognizer` и возвращает прежнего делегата, уходя.
- Вёрстка — замер PNG (`-MatchMockData` в DEBUG открывает карточку макета). Счёт — Unbounded 41, заголовок — SF 14, команды — SF 16 semibold, кружки команд 56 pt (`TeamBadgeView(size:font:)`). Подсветка строк команд в таблице — `Palette.highlight` (#21283C); отдельного «чередования» в макете нет — тёмные строки 1 и 3 и есть подсветка Ливерпуля и Арсенала.
- Состояния кнопок: включённое (закладка, напоминание) — светлая заливка, выключенное — контур. «Напомнить» скрыта — «В закладки» на всю ширину. Без подписи о задержке карточка ниже на 24 pt. В макете «Напомнить» нарисована у идущего матча, но напоминание для начавшегося матча бессмысленно (модель её прячет).
- Напоминания пересверяются (`reconcile`) при запуске — когда хранилище прочитало их из центра уведомлений — и при каждом `sceneWillEnterForeground`; матчи загружаются через `match(id:)` только для запланированных напоминаний, ошибки игнорируются.
- `StatusCell` (загрузка / пусто / ошибка с «Повторить») вынесена из «Сегодня» в `CoreUI` — общая для экранов.
- Напоминание о матче — локальное уведомление `UNUserNotificationCenter` за 15 минут до начала: работает без бэкенда, входа и APNs. Только для запланированного матча со стартом позже чем через 15 минут. Идентификатор уведомления = `MatchID.rawValue`; список напоминаний берётся из ожидающих уведомлений (переживает перезапуск). Триггер — абсолютное время (с часовым поясом). При запуске и возврате из фона напоминания пересверяются (`reconcile`): время поправляется, для начавшегося, перенесённого или отменённого матча напоминание снимается. Серверные пуши — вместе со входом через Apple.
- Напоминание показывается и когда приложение на экране: делегат `UNUserNotificationCenter` (`AppDelegate`) в `willPresent` отдаёт баннер и звук. Открытие карточки по нажатию на уведомление — следующий этап.
- Карточка НХЛ пока без таблицы; блок «Слушать под матч» скрыт до радио и плеера (D15, D16); «Поделиться» — текстом без ссылки; у матча не на сегодня в статусе и тексте дата («Завтра, 18:00», «Сб, 21 нояб · 18:00»).

### D23. Движок эфира (`CorePlayback`) — 2026-11-19
Контракт `AudioPlayer` и `PlaybackState` — в `CoreDomain`, реализация `RadioPlayer` — в `CorePlayback` (зависит только от `CoreDomain`, наружу публичен только `RadioPlayer()`). AVPlayer, AVAudioSession, Now Playing и часы — за внутренними протоколами, в тестах фейки.
- Пауза закрывает соединение, продолжение подключается заново: эфир всегда «сейчас», без отставания и без висящего соединения.
- Нет звука 30 с (`RadioPlayer.connectTimeout`) после запуска или после буферизации, провал элемента, обрыв или «конец» потока → `failed("Не удалось подключиться")`; `togglePlayPause` после ошибки подключается заново.
- Прерывание (звонок, Siri) → пауза; после него продолжаем, только если играли и система дала `shouldResume`. Пропал аудиовыход (`oldDeviceUnavailable`, наушники) → пауза.
- Таймер сна переживает смену станции; сработал → пауза, станция остаётся в плеере, таймер снят. Истёкший, но не сработавший (приложение спало) таймер снимается при продолжении. `stop()` закрывает плеер, снимает таймер и отпускает аудиосессию (`.notifyOthersOnDeactivation`).
- Таймаут подключения привязан к номеру попытки: опоздавший таймаут прошлой станции новую не роняет.
- Экран блокировки: название и подпись станции, `IsLiveStream`, rate 1/0; команды play/pause/toggle, перемотка и треки выключены.
- Info.plist: `UIBackgroundModes = [audio]`. Исключений ATS нет: в каталоге только https-потоки (http в `AVPlayer` блокирует ATS, см. «Грабли»).

### D24. Экран «Эфир» (`FeatureRadio`) — 2026-11-19
- `FeatureRadio.make(dependencies: .init(stations:player:), output: .init(openPlayer:))`; фича видит только `StationsRepository` и `AudioPlayer` из `CoreDomain`.
- Чип «Спорт» по умолчанию, выбран всегда один. Без поиска — «Подборка редакции»: станции выбранного жанра с `featuredOrder`, по нему. Поиск (без учёта регистра, пробелы по краям не считаются) — по названию и русским названиям жанров («спорт», «футбол», «хоккей», «новости»), по всему каталогу, чип не учитывается; секция «Результаты поиска». Пусто — «Ничего не нашлось».
- Каталог грузится при первом показе, по «Повторить» и при возврате из фона (если экран уже показывали); ошибка тихого обновления не стирает список.
- «Сейчас играет» — только при `item != nil`. `loading` — индикатор на кнопке, нажатие отменяет подключение; `failed` — текст ошибки вместо подписи и play (повтор). Волна — 31 столбик из макета, пульсирует только при `playing`, при «Уменьшении движения» неподвижна. Нажатие на карточку — `openPlayer`, на кнопку — `togglePlayPause`. Строка и её кнопка: текущая станция — `togglePlayPause`, другая — `play`; у играющей/подключающейся станции в строке пауза.
- Пока `playing`, фон «Сейчас играет» переливается: `CAGradientLayer` (surfaceRaised → surfaceHigh → accent 15 % → surfaceHigh → surfaceRaised) сдвигается 5 с с автореверсом; при паузе/подключении/ошибке и «Уменьшении движения» — плоский `surfaceRaised`. Анимация перезапускается в `didMoveToWindow`, `prepareForReuse` и `willEnterForeground`.
- VoiceOver (тексты — в состоянии, из форматтера): строка — «<станция>, <подпись>», значение «играет» / «подключение», действие «Слушать <станция>» / «Пауза» / «Остановить» (при подключении); кнопка карточки — «Пауза, <станция>» / «Остановить, <станция>» / «Слушать <станция>».
- Подпись карточки следует статусу: «СЕЙЧАС ИГРАЕТ» (играет, подключение; точка акцентная), «НА ПАУЗЕ» (пауза, idle) и «НЕТ СВЯЗИ» (ошибка) с точкой `textSecondary`; у подключающейся станции в строке — индикатор, как на карточке.
- Значок станции — две буквы: первые буквы двух первых слов, у одного слова — две его первые буквы.
- Вёрстка — замер PNG (`-RadioMockData` в DEBUG открывает вкладку «Эфир» на данных макета с фейковым плеером). Заголовок карточки — Unbounded 18, чипы — SF 15 semibold с полями 13 pt (SF в UIKit шире шрифта макета, так совпадает ширина чипов), подсказка поиска — `Palette.placeholder` (#757575, снят с макета). Значки play/pause залиты (в макете сплошные), значок станции в карточке — 5 линий в стиле Lucide `audio-lines`.

### D25. Мини-плеер и плеер (`FeaturePlayer`) — 2026-11-19
- `FeaturePlayer.makeMiniPlayer(player:onOpen:) -> MiniPlayerView` (это `UIView`) и `FeaturePlayer.makePlayer(player:) -> UIViewController`. У мини-плеера и плеера общая модель `PlayerViewModel` (по экземпляру на каждый), оба только отражают единственный `AudioPlayer` (`AppDependencies.player`, `RadioPlayer`). «Эфир» (`openPlayer`) и мини-плеер открывают плеер одинаково — `SceneDelegate.openPlayer()`.
- Мини-плеер виден, пока `item != nil`. Показом управляет `MainTabBarController` по `onVisibilityChange`: карточка с полями 12 pt по бокам и 12 pt над таб-баром, появление и скрытие — 0.25 с (прозрачность и сдвиг на 16 pt). Пока карточка видна, всем вкладкам `additionalSafeAreaInsets.bottom = 49 + 60 + 12`, последний элемент списка не перекрыт.
- Статус мини-плеера: «● В эфире» (акцент; точка — отдельный кружок 4.5 pt, а не символ: символ «●» в SF крупнее макета), «Подключение…», «На паузе», текст ошибки (`destructive`). Обложка — `artworkUrl600` из iTunes (600×600), а не оригинал ленты (до 3000×3000). Отвергнуты: украиноязычные/англоязычные (SportHub Media, Hockey on the Beach), заброшенные (Лёдкаст КХЛ, Звуки футбола), лента по http, лента на 18 МБ (Спортивное радио «Движение»).

### D28. Движок для выпусков подкастов — 2026-11-20
Расширение D23: тот же `RadioPlayer` играет и эфир, и выпуски (`PlaybackItem`: `.station` | `.episode(_, podcast:)`). Для эфира всё по D23 без изменений.
- Контракт (`CoreDomain/AudioPlayer.swift`): `PlaybackState(item:status:sleepTimerEndsAt:position:duration:rate:)` (у эфира `position`/`duration` nil, `rate` 1); `AudioPlayer.play(_ item:)` (+ `play(_ station:)` в расширении), `seek(to:)`, `skip(by:)`, `setRate(_:)` — у эфира ничего не делают.
- Пауза выпуска настоящая (поток не отпускаем), продолжение — `resume` с того же места, с таймаутом подключения 30 с, как у эфира. После ошибки — новый запуск с последней сохранённой позиции.
- `play(.episode)` начинает с `ListeningProgressStore.position`; прослушанный — с 0, только если позиция в хвосте (≥95 % длительности из ленты), иначе недослушанный повтор продолжается; «прослушано» не снимается. Перемотка на сохранённую позицию — после `readyToPlay` (раньше AVPlayer может её потерять и начать с 0), play — после неё. Перемотка с допуском 1 с (точная у длинного VBR MP3 может упереться в таймаут 30 с), зажата в [0, длительность] (длительности нет — только снизу). Длительность — из ленты, затем из `AVPlayerItem`.
- Позиция в состоянии — раз в 0,5 с (наблюдатель времени AVPlayer), принимается только при `playing`: при подключении AVPlayer может отдать 0 до перемотки на сохранённое место. Сохранение — раз в 10 с игры (`saveInterval`), на паузе (в т.ч. прерывание, таймер сна, наушники), при ошибке, смене выпуска/станции, `stop()` и `didEnterBackground`.
- ≥95 % (`finishedFraction`) → `markFinished` (играет дальше); конец потока → прослушан, пауза на позиции 0, следующий выпуск сам не запускается. У эфира конец потока — по-прежнему ошибка.
- Скорость (0,75–2 из UI; ≤0 игнорируется, остальное зажато в 0,5…2) действует на выпуски до перезапуска приложения; эфир всегда 1 (`defaultRate` AVPlayer сбрасываем при запуске станции).
- Экран блокировки у выпуска: время, длительность, скорость, `IsLiveStream = false`; включены −15/+30 и перетаскивание позиции, у эфира выключены. Время обновляем только при смене статуса/скорости/перемотке/длительности — дальше система ведёт его сама. Обложки на экране блокировки пока нет.
- Хранилище позиции передаётся в `RadioPlayer(progress:)` из `Services.make`; `RadioPlayer()` без хранилища — только для отладочных сборок с эфиром.
- `FeatureRadio` видит только станции (`item?.station`); выпуск в «Эфире» не показывается. `FeaturePlayer` рисует выпуск своим вариантом плеера (D25, «Плеер выпуска»).

### D29. Вкладка «Подкасты» (`FeaturePodcasts`) — 2026-11-20
- `FeaturePodcasts.make(dependencies: .init(podcasts:episodes:subscriptions:progress:player:), output: .init(openPlayer:))`; фича видит только протоколы `CoreDomain`. Два экрана → `PodcastsCoordinator` (D21): корень вкладки и push экрана подкаста в навигацию, в которую приложение обернуло корень. Координатор живёт, пока жив корень (его держит замыкание модели).
- **«Новый» выпуск** — нет записи в `ListeningProgressStore` (не начат, не прослушан) и `publishedAt ≥ дата подписки − 7 дней`. Одна функция (`PodcastsFormatter.isNew`) считает плитки, бейдж и список, поэтому они сходятся: бейдж «Подписки N» = число новых в «Новых выпусках» = сумма по плиткам; 0 — бейдж скрыт. Подписи плиток: «1 новый», «2 новых», «21 новый», «11 новых», 0 — «Всё прослушано»; лента не загрузилась и кеша нет — «Нет связи», ещё грузится — пусто. Начатый выпуск («осталось N мин») — уже не новый.
- **«Новые выпуски»** — новые и начатые (есть позиция, не прослушан) выпуски подписок вперемешку, по дате публикации, свежие первыми (как в макете: «Сегодня», «Вчера», «16 нояб · осталось 12 мин»). Подпись строки: «● Новый · <подкаст>» (светлая) или «<подкаст>» (вторичная); вторая строка — «Сегодня / Вчера / 16 нояб [2025] · 34 мин», у начатого «осталось N мин», у прослушанного «прослушано». Минуты — до ближайшей (34:10 → «34 мин»), не меньше 1; от часа — «1 ч 12 мин».
- Пилюля «Слушать» — только у первой строки списка и у выпуска, который сейчас в плеере («Пауза» при игре/подключении). Кнопка: выпуск в плеере — пауза/продолжение, другой — запуск. Нажатие на строку: выпуск в плеере — открыть плеер, другой — запуск. Так же на экране подкаста. «Скачать» и полоска загрузки — D30.
- **Сегмент по умолчанию** — «Подписки», если при открытии есть подписки, иначе «Подборка»; дальше сам не переключается. «Загрузки» сам не выбирается (D30).
- «Подборка» — весь каталог: обложка, название, автор, «Подписаться» (акцентная пилюля) / «Вы подписаны» (контурная). Подписка/отписка пересчитывает экран без запросов; качается только лента нового подкаста, если её ещё нет.
- Загрузка: каталог — при первом показе, «Повторить» и возврате из фона (ошибка тихого обновления не стирает каталог); ленты подписок — при каждом показе вкладки и возврате из фона (троттлинг 30 мин — в репозитории, D27), «потянуть вниз» — `forceRefresh: true`. Если принудительное обновление не удалось, репозиторий молча отдаёт кеш — так и показываем (ошибку видно, только когда кеша нет: «Не удалось загрузить выпуски» с «Повторить»). Без подписок — «Подпишитесь на подкасты в «Подборке»», без новых — «Новых выпусков нет».
- Плеер шлёт позицию дважды в секунду — экраны перерисовываются только при смене выпуска или статуса.
- Плитки: 3 на ширину с промежутком 12 pt, больше — прокрутка вбок. Название (Unbounded 16) поверх плашки — только пока нет обложки (как в макете): на настоящих обложках название уже нарисовано, а надпись поверх картинки не читается.
- Экран подкаста (макета нет, язык макета): системная прозрачная панель с «назад», обложка 120 pt, название Unbounded 20, автор, «Подписаться»; «Выпуски» — те же строки, «новые» только у подписанного подкаста.
- Вёрстка — замер PNG: `-PodcastsMockData` (только DEBUG) — вкладка на данных макета, подписки и позиция в наборе UserDefaults `PodcastsMockData`, плеер без звука. В макете «Вне игры · 2 новых», а в списке один новый выпуск «Вне игры» — счётчики так не сходятся, поэтому в моке второй новый выпуск «Вне игры» добавлен строкой (4 строки вместо 3). `-PodcastsRealFeeds` — каталог из пяти подкастов миграции, ленты и `RadioPlayer` настоящие, данные в наборе `PodcastsRealFeeds`. ### D31. Профиль и вход — 2026-11-20
Вход по почте и паролю через Supabase Auth, подтверждение регистрации и сброс пароля — кодом из письма (6–10 цифр, как настроено в Supabase) (`verifyOTP`, `signup`/`recovery`). Apple — позже. Спек — [profile](superpowers/specs/2026-11-20-profile-design.md).
- Бэкенд (`supabase/migrations/20261121100000_profile.sql`): `bookmarks(user_id, match_id)`, `podcast_subscriptions(user_id, podcast_id)`, `listening_progress(user_id, episode_id, position, is_finished, updated_at)`; ключ `(user_id, <id>)`, `user_id references auth.users on delete cascade`; RLS — `select/insert/update/delete` для `authenticated` по `user_id = (select auth.uid())`, у `anon` прав нет. `match_id` = `MatchID.rawValue`, `episode_id` = `EpisodeID.rawValue`, внешних ключей на матчи/выпуски нет.
- Edge Function `delete-account`: только `POST` с `Authorization: Bearer <jwt>`; id берёт `auth.getUser(jwt)` (клиент с `SUPABASE_ANON_KEY`), удаляет `auth.admin.deleteUser` (клиент с `SUPABASE_SERVICE_ROLE_KEY`), строки уходят каскадом; 200 `{deleted}` / 401 / 405 / 500. `verify_jwt = false` в `config.toml`: токен проверяет сам Auth через `getUser`.
- Клиент: `Account` в `CoreDomain`, `SupabaseAccount` в `CoreRepositories` (продукт `Auth` supabase-swift, сессия в Keychain — `KeychainLocalStorage`, `emitLocalSessionAsInitialSession: true`: сохранённая сессия сразу, даже просроченная, — без сети остаёмся во входе). Состояние `unknown` до первого события сессии; ворота считают его «без входа». Окончательный сбой обновления сессии библиотека сообщает `signedOut` — это наш выход.
- Один экземпляр: `Services.makeAccount` → `(account, userClient)`, держит `AppDependencies.account` (статически, как загрузки): два `AuthClient` делили бы одну сессию в Keychain. `userClient` — PostgREST таблиц пользователя: каждый запрос с `Authorization: Bearer` текущего токена (без входа — только `apikey`).
- Ошибки Auth → `AccountError` по коду: `invalid_credentials`, `email_not_confirmed`, `user_already_exists`/`email_exists` → `emailTaken`, `otp_expired` → `invalidCode` (так Supabase отвечает и на неверный код), `weak_password`, `over_email_send_rate_limit`/`over_request_rate_limit` или HTTP 429 → `rateLimited`; `URLError` → `network`; прочее — `unknown`.
- С включённым «Confirm email» `signUp` на уже подтверждённую почту отвечает успехом без сессии и без письма (Supabase прячет, занята ли почта). Считаем это «код отправлен»: `confirmSignUp` затем падает с `invalidCode`, человек идёт во «Вход» или «Забыли пароль?».
- Вход с неподтверждённой почтой: код отправляется заново (`resend`, сбой отправки не мешает — на шаге кода есть «Отправить ещё раз»), ошибка `emailNotConfirmed`.
- Сброс пароля: `verifyOTP(.recovery)` даёт сессию, затем `update(user: password)`. Сбой смены пароля — выход: код уже потрачен, пароль прежний, сессия восстановления не должна остаться входом.
- Состояние — всегда из сохранённой сессии (`currentSession`), события библиотеки — лишь сигнал «перечитать»: они приходят с задержкой, и запоздалое событие не должно перебить итог. Пока идёт операция аккаунта (вход, код, сброс, выход, удаление), события не публикуются, итог публикуется по её окончании — промежуточная сессия восстановления не даёт мигания `signedIn`, а мгновенно пустое хранилище — `signedOut`. `validation_failed` на `verifyOTP` (код не той длины) — тоже `invalidCode`.
- **Чистка данных** (загрузки, напоминания, локальные копии) — на `signedIn(X)` → `signedOut`, на `signedIn(X)` → `signedIn(Y)` и при запуске с сохранённым владельцем копии, если состояние разрешилось в `signedOut` (сессию потеряли, пока приложение не работало). Никогда — на `unknown` → `signedOut` без сохранённого владельца (запуск без входа).
- Выход всегда успешен локально (библиотека удаляет сессию до запроса `/logout`). Удаление аккаунта: ошибка — остаёмся во входе, успех — выход.
- Нечитаемая сессия при запуске считается выходом. Если есть сохранённый владелец — чистим всё, включая загрузки. Возможно только при запуске до первой разблокировки после перезагрузки (Keychain AfterFirstUnlock); пока принято.
- Конфликт позиции решают часы устройства (`updated_at` с клиента): телефон с часами в будущем блокирует обновления; принято.
- «Напомнить» остаётся как в D22 (закладка не нужна) и стоит за воротами входа; выход отменяет все напоминания.
- **Синхронизация** закладок, подписок и позиции (`UserDataSync.swift`, `Synced…Store`): одна схема `SyncedCollection<Item>` — словарь ключ → значение, ключ = `MatchID.rawValue` / id подкаста / `EpisodeID.rawValue`. UserDefaults: копия `<имя>.<userID>.v1`, очередь `<имя>.<userID>.queue.v1` (JSON ключ → значение или nil = удаление; последнее изменение ключа заменяет прежнее), чья копия — `<имя>.user`; имена `bookmarks`, `podcasts.subscriptions`, `podcasts.progress`. Старые ключи `bookmarks.v1`, `podcasts.subscriptions.v1`, `podcasts.progress.v1` не переносятся (без входа данных нет) и удаляются в `Services.make`.
- Состояния: `unknown` (запуск) — показываем копию последнего пользователя, не отправляем и не пишем; `signedIn(тот же)` — продолжаем; `signedIn(другой)` или `signedOut` при сохранённом пользователе (сессию потеряли, пока приложение не работало) — копия и очередь стёрты (правило чистки выше). Без входа и в `unknown` запись игнорируется — в том числе позиция плеера.
- Вход и каждый переход в `signedIn` — загрузка с сервера (принудительно) поверх неотправленной очереди, затем отправка очереди. Возврат из фона — то же, не чаще раза в 5 мин (`refreshFromServer(force:)`, троттлинг в каждом хранилище; хранилище само слушает `willEnterForeground`), под троттлингом — только отправка. Изменение — копия + очередь + отправка сразу; сбой оставляет очередь; из очереди снимается только то, что не менялось во время отправки. Ответ сервера для вышедшего/сменившегося пользователя отбрасывается.
- Позиция: локально каждый вызов, на сервер — не чаще раза в 60 с, сразу — `markFinished` и `flushProgress()`. Плеер зовёт `onProgressCheckpoint` (пауза, смена/запуск выпуска, стоп, ошибка, `didEnterBackground`); приложение передаёт `(progress as? SyncedListeningProgressStore)?.flushProgress()`. Конфликт при загрузке: неотправленная позиция остаётся, только если её `updated_at` не раньше серверного; закладки и подписки — неотправленное всегда побеждает. Загрузка и отправка не идут одновременно (`isBusy`): отправка во время загрузки ждёт её конца, загрузка во время отправки — после неё; иначе устаревший ответ затирал только что отправленное. На сервере триггер `listening_progress_keep_latest` (`before update`, `security invoker`, `search_path = ''`) оставляет строку, если `updated_at` новой позиции раньше: офлайн-очередь не перезапишет более позднюю позицию с другого телефона.
- PostgREST: `PostgrestUserDataRemote<Row>` поверх `userClient` (D31, токен — кастомным `fetch`), `upsert(onConflict: "user_id,<ключ>", returning: .minimal)`, удаление `eq(user_id) + in(<ключ>)`; `user_id` = `account.userID` (RLS `WITH CHECK`). Строка `listening_progress` кодируется плоско (`position`, `is_finished`, `updated_at` рядом с `user_id`, `episode_id`).
- Моки DEBUG (`-TodayMockData`, `-PodcastsMockData`, `-PodcastsRealFeeds`): `Services.make(account: MockAccount(), userClient: nil)` — фейковый «вошедший» аккаунт `mock`, только локально.
- **Лист входа** (`FeatureProfile.makeSignIn(account:reason:startAt:completion:)`, `SignInStart`: `motivation` / `signUp` / `signIn`): `SignInCoordinator` — `UINavigationController` `.pageSheet`, стек повторяет `state.path` модели (`SignInModel`, шаги `motivation → signUp → code`, `signIn` (`emailNotConfirmed` → `code`), `forgot → resetCode`); «назад» навигации — `didPop(toDepth:)`, закрытие жестом — `completion(false)`, вход — лист закрывается, затем `completion(true)`. Заголовки шагов (Unbounded 26, это заголовки экранов, D18): «Сохраните своё», «Создать профиль», «Код из письма», «Вход», «Сброс пароля», «Новый пароль»; кнопки «Продолжить», «Подтвердить», «Войти», «Получить код», «Сохранить и войти». Имя необязательно (пустое — «Болельщик»); кнопка активна при почте с «@» и пароле от 8 (во «Вход» — любой непустой), код — 6–10 цифр (длину задаёт Supabase, Email OTP Length; по умолчанию 8). Ошибка — одна подпись `destructive` под полями, стирается правкой любого поля. «Отправить ещё раз» — не чаще раза в 60 с от последней отправки (часы инжектируются, экран тикает раз в секунду); на шаге сброса повторно зовёт `requestPasswordReset`. Пилюли листа — 50 pt (`WidePillButton`), неактивная акцентная — `surfaceHigh` с `textSecondary`; поля — `surface`, скругление 14, высота 52.
- **Профиль**: `FeatureProfile.make(dependencies: .init(account:bookmarks:subscriptions:downloads:), output: .init(flushUserData:))`. Без входа (и в `unknown`) — заголовок и карточка мотивации (три пункта, «Создать профиль» / «У меня есть профиль» открывают лист на шаге `signUp` / `signIn`, повод `.profile` — без строки повода). Со входом — карточка аккаунта по замеру PNG (высота 79 на месте прежних плиток, кружок 52 `surfaceHigh` с буквой Unbounded 20, имя SF 18 semibold, почта SF 14, «Выйти» — контурная 34 pt SF 14 semibold), плитки на 20 pt ниже, «ЗАГРУЗКИ», «Удалить аккаунт» (`destructive`) в 20 pt под карточкой загрузок. Экран — в `UIScrollView`: низ с мини-плеером на низких экранах не прячется. Ошибка удаления — `.alert` «Не удалось удалить аккаунт» с текстом ошибки.
- **Выход**: подтверждение → `flushUserData` (лучшее усилие, не дольше 3 с — потом отменяется) → `signOut()`. Предупреждения о неотправленном нет: офлайн-выход теряет неотправленные изменения молча. `Services.flushUserData(bookmarks:subscriptions:progress:)` — публичная обёртка над `flush()` хранилищ.
- **Чистка телефона** — `AccountCleanup` (`CoreRepositories`, держит `SceneDelegate`): по тому же правилу чистки снимает все напоминания и `downloads.removeAll()`. Свой владелец в UserDefaults `account.owner` (не ключи хранилищ). Напоминания центр отдаёт асинхронно, поэтому после чистки при `signedOut` пришедшие позже тоже снимаются, пока снова не вошли.
- **Ворота**: `SceneDelegate.requireSignIn(_:then:)` — вошёл — сразу `then`; иначе лист с мотивацией поверх самого верхнего показанного экрана, `then` — только после входа. Лист входа уже сверху — ничего; верхний экран уходит (`isBeingDismissed`) — лист после окончания перехода. Фичи зовут его через `Output.requireSignIn` (ниже).
- **Лист во время запроса**: `isModalInPresentation`, кнопка «назад» скрыта, свайп назад и «Закрыть» выключены. Если лист всё же закрыли во время запроса, `completion` один раз с настоящим итогом запроса (вход не теряется). Шаг кода добавляется, только если человек всё ещё на шаге, с которого отправлял. - **Хранение** — Supabase Storage, приватное хранилище `avatars` (лимит 1 МБ, только `image/jpeg`), файл `<user id>.jpg`; RLS на `storage.objects` — читать, загружать, менять и удалять только свой файл (`20261126232300_avatars.sql`, применена). `delete-account` (v2) удаляет фото до пользователя.
- **Клиент** — `AvatarStore` (CoreDomain), `SupabaseAvatarStore`: REST Storage с токеном того же `AuthClient` (`Services.makeAccount`), копия на диске `Caches/avatars` — фото при запуске и без сети. Выход стирает копию. Ответ сервера, начатый до загрузки или удаления, их не перезаписывает (счётчик `changes`). «Нет файла» у Storage — 400 (или 404).
- **Камера** — `UIImagePickerController` с системной квадратной рамкой, фронтальная. `NSCameraUsageDescription` — «Чтобы сделать фото для вашего профиля». Разрешение: первый раз — системный запрос; отказ сейчас, раньше или отозванный в Настройках — алерт «Нет доступа к камере» с кнопкой «Настройки».
- **Галерея** — `PHPickerViewController`: системное окно, приложение получает только выбранное фото, разрешение не нужно — `NSPhotoLibraryUsageDescription` нет (Apple советует так; запрос всей медиатеки ради аватарки ревью может не принять).
- **Картинка** — квадрат из середины, 512 px, JPEG 0.8 (`AvatarImage`) — всегда в лимите хранилища.
- **Профиль** — нажатие на кружок: «Сделать фото» (если есть камера), «Выбрать из галереи», «Удалить фото» (если есть). Для `-ProfileMock` — `MockAvatarStore` в памяти.
- **Приватность** — `PrivacyInfo.xcprivacy`: фото или видео, связаны с человеком, для работы приложения; политика конфиденциальности дополнена.

## Грабли

- **«swap-monorepo» в окружении** — это название сессии в приложении, а не репозиторий. Репозиторий проекта — только `AndruhaPower/tribuna`.
- **football-data.org**: нет стадиона (`venue: null`), названия команд только на английском — переводим сами. Счёт приходит с задержкой.
- **Radio Browser**: российских станций с тегом `sport` всего одна. Каталог придётся дополнять своим списком.
- **RSS подкастов**: нет `ETag` и `Last-Modified`, условные запросы не работают — кешируем по своему расписанию. Уточнение 2026-11-20: mave и podster отдают `ETag`/`Last-Modified`, но условные запросы пока не делаем (D27).
- **iTunes Search** по «спорт»/«футбол» в `country=ru` отдаёт и украино-, англоязычные подкасты, и заброшенные — язык (`<language>`) и дату последнего выпуска проверяй по самой ленте.
- **Глобальный git** настроен на рабочую почту другого проекта. После клонирования снова задай `git config user.email pazit@yandex.ru`.
- **Профиль без входа** в макетах не нарисован, хотя приложение работает без входа.
- **Чужие проекты Supabase**: в том же аккаунте есть `swap-dev` и `trading-bot`. Tribuna принадлежит только `tribuna_db` (ref `wgwsdhyrazjzqwvnhgzk`), остальные не трогаем.
- **Имя модуля `CoreServices` занято** системным `CoreServices.framework` из iOS SDK: пустой таргет с таким именем падает на `'CoreServices/UTCoreTypes.h' file not found`, а непустой перекрывает системный модуль для всех, кто его импортирует. Поэтому слой данных называется `CoreRepositories`. Для новых модулей не бери имена системных фреймворков (`CoreServices`, `CoreData`, `CoreLocation` и т.п.).
- **supabase-swift**: `PostgrestClient(url:headers:decoder:)` без `logger:` выбирает устаревший init и даёт warning — передавай `logger: nil`. Подключаем продукты `PostgREST` и `Auth` (`.external(name:)`), без `Supabase`/`SupabaseClient`. `AuthClient` — только один на приложение (D31). Publishable-ключ передаём заголовком `apikey`.
- **Тесты в симуляторе**: `name=iPhone 17 Pro Max` без `OS=` ищет симулятор последней iOS SDK и может его не найти — указывай `OS=` установленного симулятора (`xcrun simctl list devices available`).
- **NHL Web API, `gamecenter/{id}/landing`**: у команд `commonName`/`placeName` вместо `name` (как в `score/{date}`) — общий DTO держит оба поля. Несуществующая игра — 404 (`NHLClient.NotFound` → `match(id:) == nil`). `score/now` отвечает редиректом: в curl нужен `-L`.
- **`AnyCancellable { ... }` в `@MainActor`-коде** — замыкание наследует изоляцию главного актора, а снимается из `deinit` владельца на любом потоке: Swift 6 падает на проверке изоляции. Замыкание снятия помечай `@Sendable`.
- **ATS и http-потоки радио**: в iOS 26 `NSAllowsArbitraryLoadsForMedia` не пропускает http-поток в `AVPlayer` — `-1022 … does not conform to ATS policy`, плеер сразу в `failed`. Поэтому в каталоге только https-потоки, исключений ATS в Info.plist нет. Пять http-станций (Вести FM, Маяк, КП, «Серебряный дождь», BBC 5 Live) заменены https-адресами тех же станций (проверены: 200, `audio/mpeg` или HLS, TLS 1.2+).
- **`UISlider` в iOS 26** присылает последний `valueChanged` уже после `touchUpInside`. Если по `valueChanged` «брать» бегунок (режим перетаскивания), он остаётся взятым навсегда: время на экране застывает, хотя звук идёт. Обрабатывай `valueChanged` только при `slider.isTracking`.
- **Симулятор: «Поделиться» вешает приложение** — `UIActivityViewController` синхронно ждёт XPC-ответа службы `com.apple.sharing.sharesheet` (`SFShareSheetSlotManager ensureConnectionEstablished`), главный поток стоит. Это служба симулятора, не наш код; «Поделиться» проверять на устройстве.
- **Симулятор: `.newPassword` закрывает поле жёлтой плашкой «Automatic Strong Password cover view text»** — набранный текст не виден и не попадает в поле. В `-ProfileMock` поле нового пароля — `.password` (только DEBUG); проверять автоподстановку пароля — на устройстве.
