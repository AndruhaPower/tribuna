# Журнал решений Tribuna

Зафиксированные решения и известные грабли. Перед работой прочитай целиком. Принял новое решение или наступил на грабли — допиши сюда в том же коммите.

Формат записи: номер, дата, решение, почему, следствия. Отменённое решение не удаляем, а помечаем «Отменено → D<N>».

## Решения

### D1. Репозиторий — 2026-11-19
Приватный GitHub `AndruhaPower/tribuna`, основная ветка `main`. Автор коммитов — `pazit@yandex.ru`, задан локально в `.git/config`, глобальный git не трогаем.
Bitbucket Okko и всё, что относится к ypios, сюда не переносим: это другой проект.

### D2. Цель — App Store — 2026-11-19
Проект строится как продукт для публикации и развития, не как прототип. Архитектуру закладываем сразу, без «перепишем потом».

### D3. Минимальная iOS 16 — 2026-11-19
Следствия: нельзя Observation (`@Observable`), SwiftData и прочие API iOS 17+ без `if #available`. Для реактивности доступен Combine.

### D4. Tuist, проект генерируется — 2026-11-19
`.xcodeproj` и `.xcworkspace` не хранятся в git, генерируются Tuist. Генерация одной командой из корня: `./generate`. Версия Tuist закреплена в `mise.toml`.

### D5. Модуль на каждую фичу — 2026-11-19
- `Tribuna/` — приложение, собирает фичи (таб-бар, DI, точка входа).
- `Features/Feature<Имя>/` — по модулю на фичу (экраны `Матч` и `Плеер` не вкладки, но тоже фичи): `FeatureToday`, `FeatureMatch`, `FeatureBookmarks`, `FeatureRadio`, `FeaturePodcasts`, `FeaturePlayer`, `FeatureProfile`.
- `Core/Core<Имя>/` — общий код (сеть, хранилище, аудио, дизайн-система). Модуль заводим, когда он нужен первой фиче, а не заранее.
- Фичи не зависят друг от друга. Общее выносим в Core. Core не зависит от фич.

### D6. UIKit + SnapKit, Swift 6 — 2026-11-19
UI на UIKit, вёрстка кодом через SnapKit (без storyboard и xib, кроме системного Launch Screen из Info.plist). Жизненный цикл — `AppDelegate` + `SceneDelegate`.
Swift 6 language mode со строгой проверкой конкурентности с первого коммита: потом мигрировать дороже.
Внешние зависимости подключаются через `Tuist/Package.swift`, `Tuist/Package.resolved` коммитится.

### D7. Бэкенд в этом же репозитории — 2026-11-19
Supabase-проект `tribuna_db`. Миграции и Edge Functions лежат в `supabase/` этого репозитория.

### D8. Футбол только через бэкенд — 2026-11-19
У football-data.org лимит ~10 запросов в минуту на ключ, общий для всех пользователей. Поэтому клиент не ходит в football-data.org: Edge Function или cron забирает матчи в таблицу Supabase, клиент читает оттуда. Пуш «за 15 минут до матча» тоже шлёт сервер. NHL, Radio Browser и iTunes ключа не требуют, их клиент вызывает напрямую.

### D9. Секреты не в git — 2026-11-19
Ключи API, `.env`, `Secrets.xcconfig`, `.p8`, `.p12` — только локально и в настройках Supabase. В репозитории допустим `.env.example` без значений.

### D10. Bundle ID — 2026-11-19
Приложение: `com.tribuna.app`. Модули: `com.tribuna.app.<Модуль>`. После публикации в App Store не меняется.

### D11. Граница модуля фичи — 2026-11-19
Фича наружу отдаёт только фабрику: `public enum Feature<Имя> { public static func make...() -> UIViewController }`. Всё остальное `internal`. Приложение собирает фичи и решает, что куда ведёт.
Пока все модули — таргеты (static framework) в одном `Project.swift` в корне. На отдельные проекты делим, если сборка станет медленной.
Паттерн экрана (MVVM, координаторы и т.п.) выбираем на первом настоящем экране и записываем сюда.

## Грабли

- **«swap-monorepo» в окружении** — это название сессии в приложении, а не репозиторий. Репозиторий проекта — только `AndruhaPower/tribuna`.
- **football-data.org**: нет стадиона (`venue: null`), названия команд только на английском — переводим сами. Счёт приходит с задержкой.
- **Radio Browser**: российских станций с тегом `sport` всего одна. Каталог придётся дополнять своим списком.
- **RSS подкастов**: нет `ETag` и `Last-Modified`, условные запросы не работают — кешируем по своему расписанию.
- **Глобальный git** настроен на рабочую почту okko.tv. После клонирования снова задай `git config user.email pazit@yandex.ru`.
