# Журнал решений Tribuna

Зафиксированные решения и известные грабли. Перед работой прочитай целиком. Принял новое решение или наступил на грабли — допиши сюда в том же коммите.

Формат записи: номер, дата, решение, почему, следствия. Отменённое решение не удаляем, а помечаем «Отменено → D<N>».

## Решения

### D1. Репозиторий — 2026-11-19
Приватный GitHub `AndruhaPower/tribuna`, основная ветка `main`. Автор коммитов — `pazit@yandex.ru`, задан локально в `.git/config`, глобальный git не трогаем.
Bitbucket Okko и всё, что относится к ypios, сюда не переносим: это другой проект.

### D2. Цель — App Store — 2026-11-19
Проект строится как продукт для публикации и развития, не как прототип. Архитектуру закладываем сразу, без «перепишем потом».

### D3. Минимальная iOS 16 — 2026-11-19
Следствия: нельзя Observation (`@Observable`), SwiftData и прочие API iOS 17+ без `if #available`. Для реактивности доступен Combine.

### D4. Tuist, проект генерируется — 2026-11-19
`.xcodeproj` и `.xcworkspace` не хранятся в git, генерируются Tuist. Генерация одной командой из корня: `./generate`. Версия Tuist закреплена в `mise.toml`.

### D5. Модуль на каждую фичу — 2026-11-19
- `Tribuna/` — приложение, собирает фичи (таб-бар, DI, точка входа).
- `Features/Feature<Имя>/` — по модулю на фичу (экраны `Матч` и `Плеер` не вкладки, но тоже фичи): `FeatureToday`, `FeatureMatch`, `FeatureBookmarks`, `FeatureRadio`, `FeaturePodcasts`, `FeaturePlayer`, `FeatureProfile`.
- `Core/Core<Имя>/` — общий код (сеть, хранилище, аудио, дизайн-система). Модуль заводим, когда он нужен первой фиче, а не заранее.
- Фичи не зависят друг от друга. Общее выносим в Core. Core не зависит от фич.

### D6. UIKit + SnapKit, Swift 6 — 2026-11-19
UI на UIKit, вёрстка кодом через SnapKit (без storyboard и xib, кроме системного Launch Screen из Info.plist). Жизненный цикл — `AppDelegate` + `SceneDelegate`.
Swift 6 language mode со строгой проверкой конкурентности с первого коммита: потом мигрировать дороже.
Внешние зависимости подключаются через `Tuist/Package.swift`, `Tuist/Package.resolved` коммитится.

### D7. Бэкенд в этом же репозитории — 2026-11-19
Supabase-проект `tribuna_db`. Миграции и Edge Functions лежат в `supabase/` этого репозитория.

### D8. Футбол только через бэкенд — 2026-11-19
У football-data.org лимит ~10 запросов в минуту на ключ, общий для всех пользователей. Поэтому клиент не ходит в football-data.org: Edge Function или cron забирает матчи в таблицу Supabase, клиент читает оттуда. Пуш «за 15 минут до матча» тоже шлёт сервер. NHL, Radio Browser и iTunes ключа не требуют, их клиент вызывает напрямую.

### D9. Секреты не в git — 2026-11-19
Ключи API, `.env`, `Secrets.xcconfig`, `.p8`, `.p12` — только локально и в настройках Supabase. В репозитории допустим `.env.example` без значений.

### D10. Bundle ID — 2026-11-19
Приложение: `com.tribuna.app`. Модули: `com.tribuna.app.<Модуль>`. После публикации в App Store не меняется.

### D11. Граница модуля фичи — 2026-11-19
Фича наружу отдаёт только фабрику: `public enum Feature<Имя> { public static func make...() -> UIViewController }`. Всё остальное `internal`. Приложение собирает фичи и решает, что куда ведёт.
Пока все модули — таргеты (static framework) в одном `Project.swift` в корне. На отдельные проекты делим, если сборка станет медленной.
Паттерн экрана (MVVM, координаторы и т.п.) выбираем на первом настоящем экране и записываем сюда.

### D12. Макеты — 2026-11-19
Источник дизайна — только PNG в `docs/design/` (Figma нет). Размер 780 px = 390 pt @2x: отступ 40 px в макете = 20 pt.
Цвета сняты по пикселям и лежат в `CoreUI/Palette.swift` — новые цвета добавлять туда же, хардкод цветов в фичах запрещён.

### D13. Только тёмная тема — 2026-11-19
В макетах только тёмная тема. `UIUserInterfaceStyle = Dark` в Info.plist, светлую тему не поддерживаем.

### D14. Четыре вкладки — 2026-11-19
Сегодня, Эфир, Подкасты, Профиль. Отдельной вкладки «Закладки» нет: закладки видны в «Мои события» на «Сегодня» и в «Мои закладки» в профиле. `FeatureBookmarks` остаётся модулем экрана списка закладок, открывается из профиля через приложение (фичи друг друга не знают, D5).

### D15. Плеер общий для всего приложения — 2026-11-19
Воспроизведение запускают Сегодня («Слушать эфир матча»), Матч («Слушать под матч»), Эфир и Подкасты, а мини-плеер висит над таб-баром на всех вкладках. Поэтому:
- движок воспроизведения (AVPlayer, экран блокировки, фоновое аудио, позиция) — в Core-модуле, заводим как `CorePlayback`;
- мини-плеер и полноэкранный плеер — в `FeaturePlayer`;
- прикрепляет мини-плеер к таб-бару приложение.
Плеер подкаста: скорость, −15/+30 с, таймер сна, загрузка, «Поделиться». Для радио тот же экран без перемотки и скорости (макета нет, предложение).

### D16. Контент редакции на бэкенде — 2026-11-19
Ни одно API не отдаёт: связку матча со станцией и подкастом («Слушать под матч»), «Подборку редакции» в Эфире, «Подборку» в Подкастах, русские названия команд и их аббревиатуры (LIV, ARS). Всё это — таблицы Supabase. Гербы клубов не используем, в макетах кружки с аббревиатурами.

### D17. Время по местному дню — 2026-11-19
Матчи группируются по дню в часовом поясе пользователя, не по UTC. Ночные матчи НХЛ подписываются «ночь на чт».

### D18. Шрифты — 2026-11-19
- Unbounded 500 и 700 — заголовки экранов, логотип TRIBUNA, крупный счёт матча, цифры в профиле.
- SF Pro (системный) 400–700 — весь остальной текст: списки, подписи, кнопки, таб-бар.
Unbounded — вариативный файл из Google Fonts (`Tribuna/Resources/Fonts/Unbounded.ttf`, лицензия OFL рядом), регистрируется через `UIAppFonts`. Вес задаётся осью `wght` в `Typography.display(_:_:)`; по имени PostScript (`Unbounded-Regular_Bold`) не обращаемся. Шрифты в фичах — только через `Typography`.
Размеры сняты с макета «Сегодня» по высоте заглавных: `Typography.screenTitle` — Unbounded 700 30 pt, логотип — Unbounded 16, счёт в карточке — Unbounded 24; аббревиатура команды (`TeamBadgeView`) — SF 12 semibold, заголовок секции (`SectionHeaderView`) — SF 14 semibold капсом, подпись справа — SF 13. Макет отрисован чуть более узким шрифтом, чем SF в UIKit, поэтому ширина надписей расходится до ~3 pt — подбирай размер по высоте букв, не по ширине.

### D19. Свой таб-бар — 2026-11-19
Системный таб-бар в iOS 26 плавающий «стеклянный», в макете плоский. Используем свой: `MainTabBarController` (контейнер вкладок) + `TabBarView` в приложении. Размеры замерены по пикселям макета: высота 49 pt без безопасной зоны, поля 12 pt, иконка в квадрате 22 pt с верхом на 9.5 pt, базовая линия подписи 47.7 pt, подписи SF 11 pt (semibold — активная, medium — остальные).
Иконки — геометрия Lucide (ISC, `Tribuna/Resources/Lucide-LICENSE.txt`), SVG в `Assets.xcassets/tab-*`, линия 2. В макете иконки разного масштаба, поэтому масштаб каждой подогнан её `viewBox`, а не размером в коде. SF Symbols для таб-бара не используем — не совпадают с макетом.
Вкладкам добавляется `additionalSafeAreaInsets.bottom = 49`. Мини-плеер (D15) кладётся в тот же контейнер над таб-баром. `UIDesignRequiresCompatibility` не используем — Apple его уберёт.

### D20. Футбол: pg_cron → Edge Function → таблицы — 2026-11-19
Данные football-data.org попадают в Supabase так: pg_cron вызывает Edge Function `sync-football`, она забирает матчи, команды и таблицы и пишет в таблицы `competitions`, `teams`, `matches`, `standings`, `sync_state`. Клиент только читает их (RLS: `select` для `anon`/`authenticated`, писать может только `service_role`; `sync_state` клиенту закрыта). Таблицу турнира заменяет атомарно `replace_standings` (`security definer`, `execute` только у `service_role`). Схема — `supabase/migrations/20261119120000_football.sql`, дизайн — [спек](superpowers/specs/2026-11-19-football-backend-design.md).
Live-окно: TIMED/SCHEDULED считаются live в диапазоне −3 ч…+15 мин от `utc_date` (статус у football-data меняется с задержкой), `EXTRA_TIME`/`PENALTY_SHOOTOUT` — live. Таймаут `net.http_post` в cron — 30 с.

### D21. Паттерн экрана и слой данных — 2026-11-19
Экран — MVVM: `@MainActor` ViewModel с `@Published private(set) var state`, State уже отформатирован для показа, ViewController только рисует. Публичная поверхность фичи — `Feature<Имя>.make(dependencies:output:)`, наружу фича общается замыканиями `Output`. Координатор заводим, только когда в фиче больше одного экрана. Коллекции: compositional layout + diffable data source со стабильными ID и `reconfigureItems` для обновления ячеек. Экраны с зависящими от времени данными реагируют на `willEnterForeground` (перезагрузка, смена суток) через метод ViewModel `didEnterForeground()`.
Модули: `CoreDomain` — модели и протоколы, без зависимостей; `CoreRepositories` — реализации (PostgREST, UserDefaults), от него зависит только приложение, фичи видят лишь протоколы из `CoreDomain`.
Закладки пока локальные, в UserDefaults (ключ `bookmarks.v1`, элементы `<спорт>:<id матча>`); синхронизация с бэкендом — позже. Publishable-ключ Supabase лежит в коде приложения (`AppConfig`): он публичный по замыслу, доступ ограничен RLS (только чтение), поэтому это не секрет из D9.
Тесты — Swift Testing, схема = имя модуля:
```
xcodebuild test -workspace Tribuna.xcworkspace -scheme CoreRepositories -destination 'platform=iOS Simulator,name=iPhone 17 Pro Max,OS=26.0.1'
```
Спек — [foundation-today](superpowers/specs/2026-11-19-foundation-today-design.md).

### D22. Карточка матча — 2026-11-19
- Подпись «Счёт обновляется с небольшой задержкой» показывается только для футбольного матча в статусе `live`/`paused`.

## Грабли

- **«swap-monorepo» в окружении** — это название сессии в приложении, а не репозиторий. Репозиторий проекта — только `AndruhaPower/tribuna`.
- **football-data.org**: нет стадиона (`venue: null`), названия команд только на английском — переводим сами. Счёт приходит с задержкой.
- **Radio Browser**: российских станций с тегом `sport` всего одна. Каталог придётся дополнять своим списком.
- **RSS подкастов**: нет `ETag` и `Last-Modified`, условные запросы не работают — кешируем по своему расписанию.
- **Глобальный git** настроен на рабочую почту okko.tv. После клонирования снова задай `git config user.email pazit@yandex.ru`.
- **Профиль без входа** в макетах не нарисован, хотя приложение работает без входа.
- **Чужие проекты Supabase**: в том же аккаунте есть `swap-dev` и `trading-bot`. Tribuna принадлежит только `tribuna_db` (ref `wgwsdhyrazjzqwvnhgzk`), остальные не трогаем.
- **Имя модуля `CoreServices` занято** системным `CoreServices.framework` из iOS SDK: пустой таргет с таким именем падает на `'CoreServices/UTCoreTypes.h' file not found`, а непустой перекрывает системный модуль для всех, кто его импортирует. Поэтому слой данных называется `CoreRepositories`. Для новых модулей не бери имена системных фреймворков (`CoreServices`, `CoreData`, `CoreLocation` и т.п.).
- **supabase-swift**: `PostgrestClient(url:headers:decoder:)` без `logger:` выбирает устаревший init и даёт warning — передавай `logger: nil`. Подключаем только продукт `PostgREST` (`.external(name: "PostgREST")`), без `Supabase`/`SupabaseClient`: Auth не нужен. Publishable-ключ передаём заголовком `apikey`.
- **Тесты в симуляторе**: `name=iPhone 17 Pro Max` без `OS=` ищет симулятор последней iOS SDK и может его не найти — указывай `OS=` установленного симулятора (`xcrun simctl list devices available`).
- **NHL Web API, `gamecenter/{id}/landing`**: у команд `commonName`/`placeName` вместо `name` (как в `score/{date}`) — общий DTO держит оба поля. Несуществующая игра — 404 (`NHLClient.NotFound` → `match(id:) == nil`). `score/now` отвечает редиректом: в curl нужен `-L`.
