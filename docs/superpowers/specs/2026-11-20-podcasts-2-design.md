# Подкасты, подэтап 2 (загрузки и офлайн) — проект

Дата: 2026-11-20. Статус: на согласовании. Решения пользователя: фоновые загрузки (подход A); в Профиле — счётчики и блок «Загрузки», вход и уведомления — позже отдельным этапом.

## Зачем
Болельщик заранее скачивает выпуски и слушает их без сети или на слабой (метро, самолёт, выезд). Типичный сценарий: вечером нажал «Скачать», убрал телефон — утром выпуск уже на месте.

Макеты: `4 · Подкасты.png` (пилюля «Скачать», строка «загрузка по Wi-Fi» с полоской, подпись «скачан», сегмент «Загрузки»), `5 · Плеер.png` (кнопка «Скачан»), `6 · Профиль.png` (счётчики, блок «Загрузки»).

**Цели**
- Скачать выпуск из списка или плеера; загрузка идёт в фоне, в том числе при заблокированном телефоне и выгруженном приложении.
- «Только по Wi-Fi» (по умолчанию включено): по мобильной сети загрузка ждёт Wi-Fi.
- Скачанный выпуск играет из файла — с сетью и без; позиция, скорость, экран блокировки — как у онлайн-выпуска.
- Сегмент «Загрузки» во вкладке «Подкасты» работает без сети.
- Профиль: заголовок, «Мои закладки N» / «Мои подписки N», блок «Загрузки» (переключатель, «Занято 412 МБ · 6 выпусков» с полоской, «Очистить загрузки»).
- Каталог подкастов кешируется на диске: «Подборка» и «Подписки» открываются без сети по последним данным.

**Не цели**
- Вход через Apple, переключатели уведомлений, «Турниры в ленте», «О приложении» — следующие этапы. В Профиле их нет совсем (без заглушек).
- Автоматическая загрузка новых выпусков подписок, автоудаление прослушанных — нет (только вручную).
- Лимит места, выбор качества.

**Анти-цели**
- Загрузка тихо съедает мобильный трафик при включённом «Только по Wi-Fi».
- Скачанный выпуск без сети не играет или не виден в «Загрузках» (нет каталога/ленты).
- Система удаляет скачанные файлы при нехватке места (файлы в `Caches`) или они уходят в iCloud-бэкап.
- Счётчик «Занято» врёт после удаления/очистки; «скачан» показан у выпуска, файла которого нет.

## Подходы
| | Подход | Итог |
|---|---|---|
| **A** ✅ | Фоновая `URLSession` (`background(withIdentifier:)`): система докачивает при заблокированном телефоне и закрытом приложении, «только Wi-Fi» — флагом запроса; приложение будится по окончании | Выбран пользователем |
| B | Обычная `URLSession`, пока приложение открыто | Проще, но при блокировке экрана загрузка встаёт через ~30 с; докачка и Wi-Fi — вручную. Противоречит сценарию «нажал и убрал телефон» |

## Как устроено

### Домен (`CoreDomain`)
- `EpisodeDownloads` (`@MainActor`, протокол): `downloads: [EpisodeID: DownloadState]` + паблишер; `download(_ episode:, podcast:)`, `cancel(_ id:)` (отмена идущей и удаление скачанной — одна операция «убрать»), `removeAll()`, `localFile(for:) -> URL?`, `usage: (bytes: Int64, count: Int)`, `wifiOnly: Bool` (get/set).
- `DownloadState`: `.waiting` (ждёт сети / Wi-Fi), `.downloading(progress: Double)`, `.downloaded(bytes: Int64)`, `.failed`.
- `DownloadedEpisode`: снимок `Episode` + `Podcast` + дата загрузки — список «Загрузок» строится из него, без каталога и ленты.

### Реализация (`CoreRepositories`)
- Один объект загрузок создаётся в `Services.make` при запуске (до UI) и сразу поднимает фоновую сессию `com.tribuna.app.downloads` со своим делегатом — так система, разбудив приложение, отдаёт события ему; перенос файла из временного места и запись индекса — в делегате, синхронно в `didFinishDownloadingTo`. *(моё решение)*
- `URLRequest.allowsCellularAccess = !wifiOnly`. Resume data хранит старый запрос, поэтому переключение «Только по Wi-Fi» перезапускает идущие загрузки с нуля с новым правилом; ждущие ничего не теряют. *(моё решение; shortcut — докачка с места при смене правила, если будут жалобы)*
- Файлы — `Library/Application Support/Downloads/<хеш EpisodeID>.<расширение>`, `isExcludedFromBackup`. Расширение: из пути URL аудио, если это `mp3/m4a/aac/mp4`; иначе по MIME ответа (`audio/mpeg` → mp3, `audio/mp4`, `audio/x-m4a` → m4a); иначе mp3 — без расширения AVPlayer файл может не открыть. *(моё решение)*
- Обложка выпуска (или подкаста) качается рядом с аудио (обычной сессией, после аудио; не удалась — заглушка) — офлайн строки «Загрузок» и плеер с обложкой. *(моё решение)*
- Индекс (снимки, размеры, состояние) — JSON рядом. Ключ — `EpisodeID`: повторное «Скачать» не дублирует. Запись живёт, пока пользователь её не удалит, даже если выпуск пропал из ленты или подкаст — из каталога. При запуске индекс сверяется с файлами: нет файла — записи нет.
- Восстановление после перезапуска: `getAllTasks` фоновой сессии сопоставляется с индексом (`taskDescription` = `EpisodeID`).
- `AppDelegate.application(_:handleEventsForBackgroundURLSession:completionHandler:)` передаёт обработчик загрузкам; он вызывается после `urlSessionDidFinishEvents`.
- Ошибка загрузки (не отмена) → `.failed`, повтор — снова `download`.
- Кеш каталога: `PodcastsRepository` пишет последний успешный ответ на диск (`Caches/podcasts.json`); сбой сети — отдаёт кеш, кеша нет — ошибка (как `FeedRepository`, D27).

### Плеер (`CorePlayback`)
`RadioPlayer` получает `localFile: (EpisodeID) -> URL?` (из загрузок); для выпуска играет файл, если он есть, иначе сеть. Остальное по D28.

### Экраны
- **Строки выпусков** (вкладка и экран подкаста): у строк с пилюлей «Слушать» рядом контурная «Скачать» (макет). Идёт загрузка — вместо «Скачать» во второй строке «загрузка по Wi-Fi» (или «загрузка», если Wi-Fi не обязателен; «ждёт Wi-Fi» в `.waiting`) и полоска прогресса под текстом. Скачан — в подписи «· скачан», пилюли «Скачать» нет. Ошибка — «не удалось скачать», пилюля «Скачать» снова. У любой строки долгое нажатие — меню «Скачать» / «Отменить загрузку» / «Удалить загрузку».
- **Сегмент «Загрузки»** — третий, как в макете. Скачанные и идущие загрузки, последние добавленные сверху; те же строки (подпись «<подкаст> · скачан», без «● Новый»; вторая строка — дата, длительность или «осталось N мин»/«прослушано» из `ListeningProgressStore`, размер «48 МБ»). Свайп влево — «Удалить». Пусто — «Скачанных выпусков нет». Работает без сети. Сегмент по умолчанию — по D29 (Загрузки сам не выбирается).
- **Плеер выпуска**: слева от «Поделиться» кнопка «Скачать» / «45 %» / «Скачан» (галочка, макет). Нажатие на «Скачан» — подтверждение «Удалить загрузку?».
- **Профиль** (`FeatureProfile`, D21): заголовок «Профиль» Unbounded, две плитки-счётчика (Unbounded для цифр, D18), секция «ЗАГРУЗКИ»: «Только по Wi-Fi» (переключатель), «Занято» с «412 МБ · 6 выпусков» и полоской (доля занятого от занятого + свободного места на устройстве, `volumeAvailableCapacityForImportantUsage`), «Очистить загрузки» (красным, подтверждение; нет загрузок — неактивна). Нажатие на плитки пока ничего не делает.

## Проверки
- Тесты: индекс загрузок (сохранение, сверка с файлами, удаление, очистка, подсчёт места); сопоставление задач сессии с индексом; состояние строк/сегмента/плеера/профиля из `DownloadState`; плеер берёт файл, если он есть; кеш каталога (успех пишет, сбой отдаёт кеш).
- Симулятор: скачать выпуск, свернуть приложение — докачался; выключить сеть (Network Link Conditioner / авиарежим на устройстве) — «Загрузки» и выпуск играют; «Очистить» — место 0. Wi-Fi-only и докачка при выгруженном приложении проверяются на устройстве.
- D30 в `docs/decisions.md`.
