# Каркас экрана и данных + экран «Сегодня» — проект

Дата: 2026-11-19. Статус: на согласовании.

## Зачем

Бэкенд футбола работает (D20). Теперь нужен клиентский каркас, на котором будут строиться все экраны, и первый настоящий экран, который его проверит. Цель — чтобы следующие экраны (Матч, Эфир, Подкасты, Профиль) делались по готовому образцу, без новых архитектурных решений.

**Цели**
- Закрепить паттерн экрана (MVVM + координаторы) и навигацию между фичами.
- Клиент данных: футбол из `tribuna_db`, хоккей из NHL Web API, локальные закладки.
- Экран «Сегодня» по макету `docs/design/1 · Сегодня.png`: полоса дней, «Мои события», секции турниров, закладки.
- Модели экранов покрыты unit-тестами.

**Не цели** (следующие этапы)
- Карточка матча — тап по матчу пока открывает заглушку `FeatureMatch`.
- Поиск (кнопка-лупа в шапке не показывается, пока поиска нет).
- Мини-плеер и «Слушать эфир матча» — нужны связки матч → станция на бэкенде (D16) и плеер (D15).
- Пуш «за 15 минут», синхронизация закладок между устройствами, вход через Apple.
- Русские названия команд НХЛ (в API их нет; показываем английские).

**Анти-цели**
- Логика в `UIViewController` (запросы, форматирование, решения) — вся она в модели экрана.
- Фича знает о другой фиче или о конкретной реализации сети (D5).
- Цвета, шрифты, отступы «на глаз» — только из `Palette`/`Typography` и замеров макета (D12, D18).

## Подходы к экрану

| | Подход | Итог |
|---|---|---|
| **A** ✅ | MVVM + координаторы: контроллер верстает и рисует состояние, модель экрана (`@MainActor`) держит логику и публикует состояние через Combine, переходы между фичами решает приложение | Выбран пользователем |
| B | VIPER / Clean Swift | 5–7 файлов на экран, слишком тяжело для одного разработчика |
| C | Однонаправленный поток (Store/Reducer) | Своя инфраструктура или тяжёлая зависимость, хуже стыкуется с UIKit |

## Как устроено

### Модули

```
CoreDomain     модели (Match, Team, Competition, Sport, MatchStatus), протоколы
               MatchesRepository и BookmarksStore. Без зависимостей.
CoreServices   реализации: SupabaseMatchesRepository (supabase-swift),
               NHLClient (URLSession), объединение футбола и НХЛ,
               UserDefaultsBookmarksStore. Зависит от CoreDomain.
CoreUI         Palette, Typography + компоненты из макета по мере надобности.
FeatureToday   экран «Сегодня». Зависит от CoreDomain и CoreUI, НЕ от CoreServices.
Tribuna (app)  собирает зависимости (CoreServices → протоколы CoreDomain),
               передаёт их фичам и обрабатывает их выходы (навигация).
```

Фича видит только протоколы — в тестах модели экрана подставляются фейки.

### Паттерн экрана (образец для всех фич)

- `<Screen>ViewModel` — `@MainActor final class`. Публикует `@Published private(set) var state: <Screen>State`. Действия пользователя — методы (`didSelectDay(_:)`, `didToggleBookmark(_:)`, `didTapMatch(_:)`). Зависимости и выходы — через `init`.
- `<Screen>State` — значение (struct/enum), уже отформатированное для показа: строки времени, счёта, подписи. Контроллер ничего не форматирует.
- `<Screen>ViewController` — подписывается на `state`, раскладывает SnapKit, отдаёт действия в модель. Списки — `UICollectionView` + compositional layout + diffable data source.
- Выход фичи — замыкания в структуре `Feature<Имя>.Output` (например, `openMatch(MatchID)`). Фабрика: `Feature<Имя>.make(dependencies:output:) -> UIViewController`.
- Координатор фичи заводим, когда внутри фичи появляется больше одного экрана; у «Сегодня» один экран — координатор не нужен.

### Данные

- **Футбол** — `supabase-swift` (Swift Package Manager через `Tuist/Package.swift`), чтение `matches` + `teams` + `competitions` за выбранный день по местному часовому поясу (D17), только включённые турниры. URL проекта и publishable-ключ (`sb_publishable_…`) — в коде конфигурации приложения: ключ публичный по замыслу Supabase, доступ ограничен RLS (D20); это не секрет в смысле D9.
- **НХЛ** — `GET https://api-web.nhle.com/v1/score/{YYYY-MM-DD}`: `games[].id, startTimeUTC, gameState, homeTeam/awayTeam {abbrev, name.default, score}, period`. Статусы НХЛ (`FUT`, `PRE`, `LIVE`, `CRIT`, `FINAL`, `OFF`) приводятся к общему `MatchStatus`. День НХЛ запрашивается так, чтобы ночные матчи (по Москве) попали в правильный местный день; подпись секции — «ночь на <день>» (D17).
- **Закладки** — локально, `UserDefaults`, множество id матчей (с префиксом вида спорта, чтобы id футбола и НХЛ не пересекались). Синхронизация между устройствами — позже, с входом через Apple.

### Экран «Сегодня»

Сверху вниз, по макету:
1. Шапка: логотип — оранжевая точка + «TRIBUNA» (Unbounded 700).
2. Заголовок «Сегодня» (Unbounded 700, `Typography.screenTitle`).
3. Полоса дней: от вчера до +6 дней (8 чипов, горизонтальная прокрутка, по умолчанию выбран сегодня). Чип: день недели и число; выбранный — светлый (`textPrimary` фон, тёмный текст).
4. «Мои события» — крупные карточки матчей выбранного дня из закладок: турнир · тур, LIVE, команды с кружками-аббревиатурами, счёт крупно. Нет закладок на день — секции нет. Кнопку «Слушать эфир матча» не показываем, пока нет связки на бэкенде.
5. Секции турниров (АПЛ, ЛЧ, … , НХЛ): заголовок секции и счётчик/подпись справа («2 матча», «ночь на чт»), карточка-список строк: время или счёт/статус, две команды, кнопка закладки.
6. Пусто за день — «Матчей нет». Ошибка сети — сообщение и «Повторить». Загрузка — индикатор.

**Обновление:** при открытии и при смене дня; pull-to-refresh; пока экран виден, выбран сегодняшний день и есть матч в игре или стартующий в ближайшие 15 минут — тихо раз в 60 секунд.

**Тап по матчу** → `Output.openMatch` → приложение показывает `FeatureMatch` (пока заглушка с названием матча).

### Проверки

- Unit-тесты моделей: `TodayViewModel` (выбор дня, группировка по турнирам и порядок секций, «Мои события» из закладок, форматирование времени/счёта/статусов, пустое состояние, ошибка и повтор, решение об автообновлении) на фейковых `MatchesRepository`/`BookmarksStore` и фиксированных «сейчас» и часовом поясе.
- Unit-тесты сервисов: разбор ответа НХЛ (фикстура `tribuna_api_report/raw/nhl_score_now.body`), приведение статусов, правило «ночь на …», хранилище закладок.
- Вёрстка: замеры по PNG, как для таб-бара (D19), и сравнение скриншота симулятора с макетом.
- Сквозная проверка в симуляторе на реальных данных `tribuna_db`.

## Что решено мной (поправь, если не так)

1. Модули `CoreDomain` (модели + протоколы) и `CoreServices` (реализации); фичи зависят только от `CoreDomain`.
2. `supabase-swift` для футбола; `URLSession` для НХЛ.
3. Закладки пока локальные.
4. Полоса дней — вчера … +6 (совпадает с окном бэкенда).
5. Поиск и «Слушать эфир матча» скрыты до своих этапов.
6. Тесты — Swift Testing (Xcode 26); если с целевой iOS 16 возникнут проблемы — XCTest.
7. Publishable-ключ Supabase хранится в коде приложения.
