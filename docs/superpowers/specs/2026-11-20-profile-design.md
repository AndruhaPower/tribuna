# Профиль и вход — проект

Дата: 2026-11-20. Статус: на согласовании. Решения пользователя: за входом — закладки матчей, подписки на подкасты, загрузки, позиция прослушивания; данные профиля — на сервере (Supabase Auth + таблицы, подход A); вход пока по почте и паролю — Apple позже (нет Team ID); напоминания остаются как сейчас (кнопка «Напомнить», D22), блока «Уведомления» в Профиле нет; «Новые выпуски» (серверные пуши) — отдельным этапом.

## Зачем
Мотивировать создать профиль: смотреть матчи, слушать эфир и выпуски можно без входа, а всё «своё» (закладки, напоминания, подписки, загрузки, «продолжить с места») — только с профилем, как любой пользовательский контент. Профиль ценен сам: закладки и подписки не теряются при смене телефона и переустановке.

Макет: `6 · Профиль.png` (карточка «Алексей · Вход через Apple · Выйти», счётчики, «Уведомления», «Загрузки»); у нас под именем — почта, «Уведомлений» нет.

**Цели**
- Регистрация и вход по почте и паролю, сброс пароля, выход, удаление аккаунта в приложении (требование App Store 5.1.1(v)).
- Действие за входом без профиля открывает лист входа с мотивацией; после входа начатое действие выполняется.
- Закладки, подписки, позиции прослушивания — в Supabase, видны только владельцу; копия на телефоне — всё работает без сети, изменения догоняют сервер.
- Профиль по макету: карточка аккаунта, счётчики, «Загрузки» (из подэтапа 2), «Удалить аккаунт».

**Не цели**
- Вход через Apple (позже, отдельной кнопкой — нужен Team ID), Google/VK; «Уведомления» («Начало событий», «Новые выпуски»); смена почты/пароля и имени из профиля; аватар-картинка; «Турниры в ленте», «О приложении».
- Перенос данных, накопленных без входа: без входа их не бывает (всё за входом); приложение ещё не выпущено.

**Анти-цели**
- Закладка/подписка «пропала» после смены телефона или потери сети.
- Человек без профиля упирается в стену: смотреть, слушать и листать «Подборку» можно без входа.
- После выхода на телефоне остаются чужие данные (закладки, напоминания, загрузки предыдущего аккаунта).
- Позиция прослушивания шлёт запрос на сервер каждые 10 с.
- Удаление аккаунта оставляет данные на сервере.

## Подходы
| | Подход | Итог |
|---|---|---|
| **A** ✅ | Supabase Auth (почта + пароль; Apple — позже) + таблицы с RLS `user_id = auth.uid()`; копия на телефоне, запись сначала локально, потом на сервер | Выбран пользователем |
| B | iCloud / CloudKit без своего аккаунта | Нет «Выйти», имени, серверного использования данных (будущие пуши) — не про профиль |

## Как устроено

### Бэкенд (миграции + Edge Function; применяет пользователь)
- Таблицы: `bookmarks(user_id, match_id, created_at)`, `podcast_subscriptions(user_id, podcast_id, subscribed_at)`, `listening_progress(user_id, episode_id, position, is_finished, updated_at)`; ключ — `(user_id, <id>)`; `user_id references auth.users on delete cascade`; RLS: `select/insert/update/delete` только свои строки, `anon` — ничего.
- Edge Function `delete-account` (JWT пользователя обязателен): удаляет пользователя через service role — данные уходят каскадом. (Когда появится Apple — добавить отзыв токена Apple.)

### Домен (`CoreDomain`)
- `Account` (`@MainActor`): `state: AccountState` (`.signedOut` | `.signedIn(User)`, `User(id, name, email)`), паблишер; `signUp(name:email:password:)` → нужен код из письма; `confirmSignUp(email:code:)`; `signIn(email:password:)`; `requestPasswordReset(email:)`; `resetPassword(email:code:newPassword:)`; `signOut()`; `deleteAccount()`. Ошибки — понятным перечнем (неверный пароль/почта, почта не подтверждена, почта занята, неверный код, слишком часто, нет сети).
- Существующие `BookmarksStore`, `SubscriptionsStore`, `ListeningProgressStore` — тот же контракт; без входа они пустые и запись игнорируют.

### Реализация (`CoreRepositories`)
- Подключается продукт `Auth` supabase-swift (сейчас только `PostgREST`): сессия в Keychain (по умолчанию библиотеки), обновление токена — библиотекой. PostgREST-запросы к таблицам пользователя идут с его токеном; каталоги (матчи, станции, подкасты) — как сейчас.
- Синхронизация (одна схема для трёх хранилищ): при входе — загрузить всё с сервера и заменить локальную копию; изменение — сразу в локальную копию и в очередь отправки (UserDefaults, на пользователя); очередь отправляется сразу, при возврате из фона и запуске; сбой — остаётся в очереди. При входе на другом телефоне — серверные данные; при открытии вкладок/возврате из фона — перезагрузка с сервера (не чаще раза в 5 мин) поверх неотправленной очереди.
- Позиция: локально как сейчас (каждые 10 с); на сервер — на паузе, смене выпуска, уходе в фон и не чаще раза в 60 с во время игры. Конфликт — побеждает более поздний `updated_at`.
- `listening_progress.episode_id` — текст `EpisodeID.rawValue` (`<id подкаста>:<guid>`, без guid — URL аудио, D27): одинаков на всех телефонах; внешнего ключа нет (выпусков на сервере нет). Загрузки на сервере не учитываются — на новом телефоне их нет, это нормально.
- Выход: всегда успешен локально (сбой `signOut` в Supabase без сети игнорируется). Очистить локальные копии и очереди (перед выходом — попытка отправить очередь до 3 с, без предупреждения (D31)), отменить все напоминания, удалить все загрузки (`removeAll`), выйти из Supabase.

- Сессию не удалось обновить окончательно (аккаунт удалён с другого телефона) — тот же выход, без вопросов. *(моё решение)*
- Удаление аккаунта: ошибка — «Не удалось удалить аккаунт. Попробуйте позже», остаёмся в профиле; успех — локальный выход. *(моё решение)*
- Почта: подтверждение регистрации и сброс пароля — **6-значным кодом из письма** (`verifyOTP`, типы `signup`/`recovery`), без ссылок и возврата в приложение по URL. Пароль — от 8 символов. *(моё решение)*

### Ворота и лист входа
- Без входа: «В закладки» / «Напомнить» (карточка матча), «Подписаться», «Скачать» (строки, меню, плеер) → лист входа; после успешного входа действие выполняется. Позиция без входа не сохраняется и не восстанавливается (выпуск всегда с начала, без «осталось N мин»).
- «Мои события» на «Сегодня» без входа — не показываются. Сегменты «Подписки» и «Загрузки» без входа — видны, внутри — приглашение войти (та же мотивация и кнопка). Сегмент по умолчанию без входа — «Подборка».
- Лист входа (модальный, `.pageSheet`, навигация внутри листа) *(моё решение — тексты и шаги)*:
  1. **Мотивация**: заголовок Unbounded «Сохраните своё», строка по поводу (закладка — «Закладки на матчи и напоминания о начале»; подписка — «Подписки и счётчик новых выпусков»; загрузка — «Выпуски без интернета»), три пункта пользы («Закладки и напоминания о матчах», «Подписки и новые выпуски», «Слушайте с того же места на любом iPhone»), акцентная «Создать профиль», контурная «У меня есть профиль», «Не сейчас».
  2. **Регистрация**: «Имя», «Почта», «Пароль» (от 8 символов, показать/скрыть) → «Продолжить» → **код**: «Мы отправили код на <почта>», поле на 6 цифр (автоподстановка из письма — `.oneTimeCode`), «Отправить ещё раз» (не чаще раза в 60 с).
  3. **Вход**: «Почта», «Пароль» → «Войти»; «Забыли пароль?» → почта → код + новый пароль. Вход с неподтверждённой почтой — сразу шаг кода (код отправляется заново).
  Ошибки — подписью под полем, по-русски; кнопка неактивна, пока поля не заполнены.
- Фичи друг о друге не знают (D5): фича зовёт `output.requireSignIn(reason, then:)`; приложение показывает лист (он живёт в `FeatureProfile`) и вызывает `then` после входа.

### Профиль (`FeatureProfile`, расширяет экран подэтапа 2)
- Без входа: заголовок «Профиль», карточка мотивации (те же три пункта) с «Создать профиль» / «У меня есть профиль» (открывают лист входа на нужном шаге); больше ничего.
- С входом (макет): карточка — кружок с первой буквой имени (Unbounded), имя, почта (вместо «Вход через Apple»), контурная «Выйти» (подтверждение «Выйти из профиля? Загрузки будут удалены с телефона»); счётчики; «ЗАГРУЗКИ» — как сейчас; внизу «Удалить аккаунт» (красным, подтверждение «Удалить аккаунт? Закладки, подписки и история прослушивания удалятся навсегда»).
- Имя — из регистрации, в `user_metadata.full_name`; пустое — «Болельщик», буква «Б».

### Напоминания
Как сейчас (D22), за воротами; не требует закладки: кнопка «Напомнить» в карточке матча. Без входа кнопок нет смысла показывать отдельно — обе ведут в лист входа. Выход отменяет все напоминания.

## Что нужно от пользователя
1. Supabase → Authentication → Providers → Email: включён, «Confirm email» включён; минимальная длина пароля 8.
2. Supabase → Authentication → Email Templates: в «Confirm signup» и «Reset password» вставить код `{{ .Token }}` (тексты дам).
3. Почта: встроенная отправка Supabase — несколько писем в час на весь проект, годится для разработки. До выпуска — свой SMTP (например, Яндекс/Unisender/Resend) в Authentication → SMTP Settings.
4. `supabase db push` и `supabase functions deploy delete-account`.

## Проверки
- Тесты: ворота (без входа действие → запрос входа, после входа — выполнено); синхронизация на фейковом сервере (вход заменяет копию, изменение офлайн → очередь → отправка, сбой оставляет в очереди, конфликт позиции по времени, позиция не чаще 60 с); выход чистит всё (копии, очереди, напоминания, загрузки); шаги листа входа и ошибки (модель); состояния Профиля (без входа / с входом / без имени); RLS — SQL-проверка через MCP после миграции (чужие строки не видны).
- Симулятор: регистрация на тестовую почту (код из письма), закладка → видна в Supabase, выход → пусто, вход → вернулась; сброс пароля; удаление аккаунта → строк нет.
- D31 в `docs/decisions.md`.
