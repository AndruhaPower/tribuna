# Профиль и вход — план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development.

**Goal:** Профиль по почте и паролю (Supabase Auth); закладки, подписки, позиция прослушивания, загрузки — только с профилем, данные на сервере с копией на телефоне.
**Architecture:** `Account` и причины входа — в CoreDomain; реализация на продукте `Auth` supabase-swift и PostgREST с токеном пользователя — в CoreRepositories; хранилища закладок/подписок/позиции становятся синхронизируемыми с очередью отправки за прежними протоколами; лист входа и Профиль — в FeatureProfile; фичи просят вход через `Output.requireSignIn`.
**Spec:** `docs/superpowers/specs/2026-11-20-profile-design.md`

## Global Constraints
- D3–D6, D11, D12, D15, D17–D30 (паттерн экрана D21, фичи не зависят друг от друга D5, Palette/Typography, Unbounded — только заголовки и цифры D18, замеры PNG 780 px = 390 pt, возврат из фона, только портрет).
- Новая зависимость — только продукт `Auth` уже подключённого supabase-swift (пересмотр «Грабли: только PostgREST» — записать в D31).
- Секреты в код не попадают; publishable-ключ — как сейчас (`AppConfig`). Миграции и функции — файлами, применяет пользователь (`supabase db push`, `supabase functions deploy delete-account`). Supabase-проект только `tribuna_db`.
- Тесты: `./generate && xcodebuild test -workspace Tribuna.xcworkspace -scheme <Схема> -destination 'platform=iOS Simulator,name=iPhone 17 Pro Max,OS=26.0.1' -derivedDataPath /private/tmp/claude-502/tribuna-dd` — ненулевое число тестов.
- Русские комментарии и тексты; коммиты на русском с `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus
1. Выход/смена аккаунта: на телефоне не остаётся чужих закладок, подписок, позиций, очередей, напоминаний, загрузок. Тест `signOutWipesEverything` (Task 2) и `accountCleanupOnSignOut` (Task 3).
2. Нет сети при изменении → изменение видно сразу, уходит на сервер позже, не теряется при перезапуске. Тест `offlineChangeQueuedAndFlushedAfterRelaunch` (Task 2).
3. Вход на «новом телефоне»: локальная копия заменяется серверной, неотправленная очередь (её нет у нового) не мешает. Тест `signInReplacesLocalWithRemote` (Task 2).
4. Позиция: на сервер не чаще раза в 60 с во время игры, но всегда на паузе/фоне/смене. Тест `progressPushThrottled` (Task 2).
5. Без входа действие не выполняется молча и не теряется: после входа выполняется, после «Не сейчас» — нет. Тесты `gatedActionRunsAfterSignIn` / `gatedActionDroppedOnCancel` (Task 4).

```swift
// CoreDomain
public struct UserProfile: Sendable, Equatable { public let id: String; public let name: String?; public let email: String }
public enum AccountState: Sendable, Equatable { case unknown, signedOut, signedIn(UserProfile) }   // unknown — сессия ещё читается при запуске
public enum AccountError: Error, Equatable, Sendable {
    case invalidCredentials, emailNotConfirmed, emailTaken, invalidCode, weakPassword, rateLimited, network, unknown
}
public enum SignInReason: Sendable, Equatable { case bookmark, reminder, subscription, download, profile }
@MainActor public protocol Account: AnyObject {
    var state: AccountState { get }
    var statePublisher: AnyPublisher<AccountState, Never> { get }
    var userID: String? { get }                                   // nil без входа
    func signUp(name: String, email: String, password: String) async throws   // AccountError; после — нужен код
    func confirmSignUp(email: String, code: String) async throws              // → signedIn
    func resendSignUpCode(email: String) async throws
    func signIn(email: String, password: String) async throws                 // emailNotConfirmed — код отправлен заново
    func requestPasswordReset(email: String) async throws
    func resetPassword(email: String, code: String, newPassword: String) async throws  // → signedIn
    func signOut() async                                          // всегда успешно локально
    func deleteAccount() async throws                             // успех → signedOut
}
// CoreRepositories
public enum Services { … static func make(...) } // + account: Account, + userClient для таблиц пользователя (Task 2)
```

**Interfaces:** Consumes `Account` (Task 1). Правила (из спеки): без входа — пусто, запись игнорируется; вход → загрузить всё с сервера и заменить локальную копию; изменение → локальная копия + очередь (UserDefaults, ключ с `userID`) → отправка сразу; сбой — остаётся; выход → копия и очередь стёрты. Позиция: локально каждый вызов, на сервер — не чаще 60 с, а также немедленно при `flushProgress()` (вызывает плеер/приложение на паузе, смене выпуска, уходе в фон); конфликт — больший `updated_at`.

### Task 3: Лист входа, Профиль, проводка в приложении

**Files:** Modify/Create `Features/FeatureProfile/Sources/*` (экран Профиля в двух состояниях, `SignInCoordinator` + экраны листа: мотивация, регистрация, код, вход, сброс), `FeatureProfile.swift`; `Tribuna/Sources/SceneDelegate.swift`, `AppDependencies.swift`; новый `Tribuna/Sources/AccountCleanup.swift`. Test: `Features/FeatureProfile/Tests/*`, `TribunaTests` нет — логику очистки держать в `CoreRepositories` или тестируемом типе фичи (решение исполнителя, тест обязателен).

**Interfaces — Produces:**
```swift
public enum FeatureProfile {
    public static func make(dependencies: Dependencies, output: Output) -> UIViewController     // вкладка
    public static func makeSignIn(account: Account, reason: SignInReason, startAt: SignInStart,
                                  completion: @escaping @MainActor (Bool) -> Void) -> UIViewController  // лист; true — вошёл
}
public enum SignInStart { case motivation, signUp, signIn }
```
Приложение: `requireSignIn(reason, then:)` — если вошёл, сразу `then()`; иначе показать лист поверх текущего экрана, `then()` только при `true`. Очистка при переходе `signedIn → signedOut` (выход, удаление, сбой сессии): `reminders` — отменить все `scheduled`; `downloads.removeAll()`; хранилища чистятся сами (Task 2).

Тексты — точно из спеки (мотивация, шаги, ошибки, подтверждения). Ошибки по-русски: `.invalidCredentials` «Неверная почта или пароль»; `.emailTaken` «Эта почта уже зарегистрирована — войдите»; `.invalidCode` «Неверный или устаревший код»; `.weakPassword` «Пароль — от 8 символов»; `.rateLimited` «Слишком часто. Попробуйте через минуту»; `.network` «Нет соединения»; `.unknown` «Что-то пошло не так. Попробуйте ещё раз».

- [ ] **Step 1: Тесты моделей:** шаги листа (`motivation → signUp → code → done`, `signIn` с `emailNotConfirmed` → `code`, `forgot → resetCode → done`), кнопки неактивны без полей/пароль < 8, «Отправить ещё раз» не чаще 60 с (часы инжектируются), ошибки → тексты; Профиль: без входа (мотивация), с входом (имя, почта, буква; без имени «Болельщик»/«Б»), выход с подтверждением, удаление с подтверждением и ошибкой; `accountCleanupOnSignOut`.

- [ ] **Step 4:** Тесты `FeatureProfile` зелёные, сборка; в симуляторе — скриншоты Профиля (оба состояния) и шагов листа на фейковом аккаунте (DEBUG-флаг `-ProfileMock` с фейковым `Account`).
